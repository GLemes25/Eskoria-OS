Claude, precisamos implementar o `BootManager` do "Eskoria OS" no arquivo principal da aplicação (ex: `src/app/page.tsx`). Este componente atuará como uma state machine (máquina de estados) rigorosa para controlar a sequência de inicialização antes de liberar o acesso ao componente `<Desktop />`.

Crie a lógica utilizando um único estado `bootPhase` (iniciando em 0) e um `useEffect` centralizado que gerencie as transições via `setTimeout`. É obrigatório incluir a lógica de `clearTimeout` no retorno do useEffect para evitar memory leaks.

O container principal do BootManager (usado nas fases 0 a 3) deve usar as classes Tailwind `h-dvh w-screen bg-black overflow-hidden select-none flex flex-col` e aplicar a fonte `JetBrains Mono`.

DETALHAMENTO DO FLUXO DE FASES (TIME-BASED):

- Phase 0 (Duração: 1500ms): Renderize um container no canto superior esquerdo (`p-4` ou `p-6`). Exiba duas tags `<p>` com texto em branco (`text-white`), tamanho pequeno (`text-sm`), leading apertado (`leading-tight`) e opacidade leve (`opacity-80`). Linha 1: "Inicializando K.A.T. Kernel...". Linha 2: "Carregando módulos base...".
- Phase 1 (Duração: 1000ms): Retorne apenas o container base, 100% preto e vazio.
- Phase 2 (Duração: 3000ms): Renderize um componente interno (no mesmo arquivo) chamado `<CustomBoot />`. Este componente deve centralizar o conteúdo absoluta e perfeitamente (`flex items-center justify-center h-full w-full`). - Phase 3 (Duração: 3000ms): Retorne apenas o container base, 100% preto e vazio novamente.
- Phase 4 (Fase Final): O boot terminou. Renderize EXCLUSIVAMENTE o componente `<Desktop />`. O `<Desktop />` não deve ficar preso dentro do container preto do BootManager; retorne-o diretamente.
